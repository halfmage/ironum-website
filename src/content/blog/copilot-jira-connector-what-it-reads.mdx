**Short answer:** You can connect Jira to Microsoft 365 Copilot in three ways. Which one
fits depends on three things: whether you run Jira Cloud or Data Center, which Microsoft
license you have, and whether Copilot needs to read the comments.

*Updated 17 November 2026.* The first version of this article covered only Microsoft's own
connector. It left out live connectors such as Atlassian Rovo, which can also change Jira
data since 9 November 2026. If you run Jira Cloud, that changes the answer.

## Route 1: Microsoft's Jira Connector

This is the connector Microsoft builds for Jira. An administrator sets it up once. It reads
Jira on a schedule, stores the issues in Microsoft 365, and Copilot answers from that copy.

### Which Jira Versions Does It Support?

| | Jira Cloud | Jira Data Center |
|---|---|---|
| Supported | Yes | Version 8.14 and later |
| Extra setup | None | Microsoft's connector agent on a Windows machine, plus Microsoft's plugin from the Atlassian Marketplace |
| Comments and attachments | Not indexed | Only after a request to Microsoft Support |

Jira Server is not supported. On Jira Data Center 11, check the plugin's Marketplace listing
before you start.

### Which License Does Copilot Need?

The Microsoft 365 Copilot add-on, or Microsoft 365 E7. Copying Jira into Microsoft 365 is
free on any plan, but answering from it is not.

| License | Jira in Microsoft Search | Jira in Copilot answers |
|---|---|---|
| Microsoft 365, any plan | Yes | No |
| Microsoft 365 + Microsoft 365 Copilot add-on | Yes | Yes |
| Microsoft 365 E7 | Yes | Yes |
| Microsoft 365 + Copilot Studio | Yes | Only in agents |
| Microsoft 365 Copilot pay-as-you-go | Yes | Only in agents |

That is how a team ends up with a working connector, Jira issues in Microsoft Search, and an
empty answer in Copilot Chat.

### Does the Copilot Jira Connector Index Comments?

On Jira Cloud, no. Microsoft lists the fields it copies: title, description, status,
project, dates, assignee, priority and custom fields you pick. Comments are not on the list,
and there is no setting to add them.

This matters if your team agrees on things in the comments, as in the example above. A
Copilot that sees the description but not the thread summarizes the ticket as it was
written, not as it was agreed. On Jira Cloud, test whether route 2 closes that gap.

### Permissions and Freshness

- **Permissions:** choose the mode "Only people with access to this data source". The connector then matches Jira users to Microsoft 365 accounts by email address. If the addresses differ, people miss issues they can see in Jira.
- **Unsupported permission types:** "Any user logged in" (Cloud) and "Any logged-in user" (Data Center) cannot be checked. On Data Center, those issues are hidden from everyone in Copilot.
- **Freshness:** the copy lags behind Jira. On Data Center, the default is an update every 15 minutes and a full crawl once a day. An issue changed ten minutes ago may not be in Copilot's answer yet.

## Route 2: The Atlassian Rovo Connector

Atlassian Rovo is a **live connector** in Microsoft's catalog (Microsoft calls it
"federated"). Copilot asks Jira at the moment you ask, with your own Jira login, so it only
sees what you can see. Nothing is copied into Microsoft 365.

Since 9 November 2026, live connectors can also change data. Microsoft names Rovo as one
that creates and updates Jira work items, in Copilot Chat and Cowork.

### How to Set It Up

1. **Check the basics:** Jira Cloud, and the Microsoft 365 Copilot add-on (or E7) for every user.
2. **Admin:** in the Microsoft 365 admin center, go to Copilot connectors, Your connections, and turn on Atlassian Rovo. If your tenant blocks apps from outside publishers, turn this connector on by itself.
3. **Each user, once:** in Copilot Chat, open the … menu, Settings, Sources, connect the source and sign in with the Atlassian account.

Microsoft does not document which Jira data the Rovo connector can read. Atlassian's own MCP
server has a tool for issue comments, so test the connector with a question that only a comment
can answer, for example "What did we agree about the export format in ABC-123?".

### What It Costs

Microsoft charges nothing extra for connectors if you have the Copilot add-on. On the
Atlassian side, calls to Atlassian's MCP server are free for single lookups (one issue, one
page) and changes; searches across Atlassian products cost 1 to 10 Rovo credits from
your plan's allowance. From 3 December 2026, Atlassian bills extra credits automatically
unless an admin turns that off. Neither company documents whether the Rovo connector's calls
are counted the same way, so watch your Rovo usage in the first weeks.

### Where It Falls Short

- It needs Atlassian Cloud.
- Every user has to connect it once.
- Copilot processes your Jira content in Microsoft 365. If that is not allowed for some projects, this route is out for them.

## Route 3: A Copilot Studio Agent

This fits one specific job, for example an agent that sorts incoming bugs. In Copilot
Studio, you add Atlassian's MCP server to the agent as a tool. (MCP is the standard way AI
assistants call other systems.)

- **Server address:** take it from Atlassian's current documentation. Some older guides use an address ending in /v1/sse.
- **Sign-in:** Microsoft's Copilot Studio team recommends "Dynamic discovery".
- **Safe defaults:** Atlassian switches off the tools that delete Jira data or manage projects until an admin turns them on.

Jira only accepts a new issue when every required field is filled. If creating issues from
your agent fails, check that first.

An agent can also use Microsoft's Jira connector (route 1) as its knowledge source, for Jira
Cloud and Data Center. That works with a Copilot Studio license, without the Copilot add-on.

## Connected, but Copilot Doesn't Answer? Check These

1. **License:** without the Microsoft 365 Copilot add-on (or E7), Copilot Chat does not answer from Jira.
2. **Comments:** if the answer is in a comment, route 1 on Jira Cloud cannot find it.
3. **Email addresses:** Jira emails must match the Microsoft 365 sign-in names.
4. **Connector account:** the Jira account route 1 reads with needs "Browse projects" for every project.
5. **Permission types:** the connector cannot check "Any user logged in" (Cloud) or "Any logged-in user" (Data Center). Test projects that use them.
6. **Rovo connector:** has each user connected it under Settings, Sources?

## What About Jira Data Center and Jira Server?

**Data Center:** route 1 works, with the Windows agent and the Marketplace plugin. Comments
come only after a request to Microsoft Support. Microsoft's catalog also lists connectors from
other companies, some of which index comments. Route 2 and Atlassian's tools in route 3 need Atlassian
Cloud, and we found no documented way for Copilot to change Data Center issues. Atlassian ends Data Center
on 28 March 2029.

**Server:** neither of Microsoft's Jira connectors supports it. Some partner connectors list it.

## When Is Copilot Not the Right Tool?

Copilot fits when you run Jira Cloud or a supported Data Center version, have the licenses,
and may process your Jira content in Microsoft 365. It fits less well when:

- your content may not be processed in Microsoft 365,
- you run Jira Server, or need Data Center comments without a request to Microsoft Support,
- you need sources that have no connector.

Then a search system you control is the better fit. It reads Jira and Confluence through
their APIs, keeps the permissions people already have, and runs where you decide. That is what we build as [enterprise RAG](/services/enterprise-rag/), and for Jira and
Confluence as a [fixed-scope Jira and Confluence AI pilot](/services/jira-confluence-ai/). How it works:
[RAG over Jira and Confluence, self-hosted in the EU](/resources/blog/rag-jira-confluence-self-hosted-eu/).

Until then, one method works on any license: paste the issue in and give the AI the context
yourself. Our free
