**Kurz gesagt:** Microsoft 365 Copilot kann Jira über einen Connector lesen, aber nur, wenn
die IT-Administration ihn einrichtet und Sie die Add-on-Lizenz Microsoft 365 Copilot haben.
Mit einer normalen Microsoft-365-Lizenz erscheinen Jira-Vorgänge in Microsoft Search, in
Copilots Antworten dagegen nie. (Mit einer Copilot-Studio-Lizenz oder Pay-as-you-go-Abrechnung
können Agents sie nutzen, Copilot Chat aber weiterhin nicht; Details in der Lizenztabelle
unten.)

Wenn der Connector also eingerichtet ist und Copilot trotzdem antwortet, als gäbe es Ihr
Backlog nicht, ist womöglich nichts kaputt. Ob es funktioniert, hängt an drei Dingen:
welches Jira Sie betreiben, welche Lizenz Sie haben und was der Connector tatsächlich
übernimmt. Dieser Beitrag geht alle drei durch, auf Basis der Microsoft-Dokumentation mit
Stand 8. Oktober 2026. Microsoft aktualisiert diese Seiten häufig; prüfen Sie vor einer
Entscheidung die verlinkten Quellen.

## Auf einen Blick

- Microsoft hat **zwei** Jira-Connectors: einen für Jira Cloud und einen für Jira Data Center. Für Jira Server gibt es keinen.
- Das Indexieren ist kostenlos. **Antworten aus dem Index setzen das Add-on Microsoft 365 Copilot voraus** (oder Microsoft 365 E7).
- **Kommentare:** Der Jira-Cloud-Connector indexiert sie nicht, und Microsoft beschreibt keine Option dafür. Bei Data Center gibt es Kommentare und Anhänge nur auf Anfrage beim Microsoft-Support.
- Ist die Berechtigungsspiegelung aktiv, **verweigert der Data-Center-Connector den Zugriff** auf alles, was er nicht auswerten kann. Für Jira Cloud dokumentiert Microsoft eine nicht unterstützte Berechtigungsart, aber keine allgemeine Regel.
- Die Daten kommen zeitversetzt an (Data Center: standardmäßig alle 15 Minuten, einmal täglich vollständig). Die neuesten Änderungen können also fehlen.

Microsoft nennt diese Integrationen Microsoft-365-Copilot-Connectors. In älterer
Dokumentation und in Teilen der Einrichtung, etwa beim Connector Agent und beim Plugin im
Atlassian Marketplace, heißt dieselbe Technik Microsoft Graph Connectors.

## Welche Jira-Versionen unterstützt der Copilot-Connector?

Jira Cloud und Jira Data Center, über zwei verschiedene Connectors. Jira Server wird nicht
unterstützt.

| | Jira-Cloud-Connector | Jira-Data-Center-Connector |
|---|---|---|
| Unterstütztes Jira | Nur Jira Cloud | Jira Data Center (Microsofts Plugin unterstützt 8.10.0 bis 10.5.1) |
| Jira Server | Nicht unterstützt | Nicht unterstützt |
| Zusätzliche Infrastruktur | Keine | Microsoft Graph Connector Agent auf einem Windows-Rechner im selben Netzwerk, ab Version 3.1.15.0 |
| Zusätzliche Software in Jira | Keine | Microsofts Plugin aus dem Atlassian Marketplace |
| Kommentare und Anhänge | Nicht als indexiert aufgeführt | Nur auf Anfrage beim Microsoft-Support |

Vor einem Upgrade lohnt ein Blick auf ein Detail. Microsofts Übersichtsseite zum
Data-Center-Connector nennt Version 8.14 und neuer, die Bereitstellungsseite dagegen 8.10.0
bis 10.5.1 für das Plugin. Auf den Bereich 8.14 bis 10.5.1 passen beide Angaben. Wer Jira
Data Center 11 betreibt, prüft vorher den Eintrag im Marketplace.

## Welche Lizenz braucht Copilot, um aus Jira zu antworten?

Das Add-on Microsoft 365 Copilot oder Microsoft 365 E7. Jira mit einem Connector von
Microsoft zu indexieren, kostet in jedem Microsoft-365-Mandanten nichts extra. Diesen Index
für Copilots Antworten zu nutzen, ist in der Basislizenz nicht enthalten.

| Lizenz | Jira in Microsoft Search | Jira in Copilot-Antworten und Agents |
|---|---|---|
| Microsoft 365, jeder Plan | Ja | Nein |
| Microsoft 365 + Add-on Microsoft 365 Copilot | Ja | Ja |
| Microsoft 365 E7 | Ja | Ja |
| Microsoft 365 + Copilot-Studio-Lizenz | Ja | Nur Agents, keine Copilot-Antworten |
| Microsoft 365 Copilot Pay-as-you-go | Ja | Nur Agents, keine Copilot-Antworten |

So kommt ein Team zu einem funktionierenden Connector, zu Jira-Vorgängen in Microsoft Search
und zu einer leeren Antwort in Copilot Chat.

Für die Einrichtung braucht es zwei Arten von Administratorrechten: die Rolle
KI-Administrator im Microsoft 365 Admin Center und Administratorzugriff auf der Jira-Seite.

## Indexiert der Copilot-Jira-Connector Kommentare?

Bei Jira Cloud nicht, bei Jira Data Center nur auf Anfrage. Für den Jira-Cloud-Connector nennt Microsoft diese indexierten Felder:
Titel, Vorgangsbeschreibung, Status, Projektname, Erstellungs- und Änderungsdatum,
Bearbeiter und Priorität. Benutzerdefinierte Felder lassen sich ergänzen; fehlt ein
ausgewähltes Feld bei einem Vorgangstyp, bleibt es leer. Kommentare stehen nicht auf der
Liste, und eine Einstellung, um sie hinzuzufügen, beschreibt Microsoft nicht.

Diese Lücke wiegt schwerer, als sie aussieht. In den meisten Teams steht die eigentliche
Entscheidung in den Kommentaren: die Klarstellung aus der Entwicklung, der Sonderfall, den
jemand angesprochen hat, der Grund für den geänderten Umfang. Ein Copilot, der die
Beschreibung kennt, aber nicht den Verlauf, fasst das Ticket so zusammen, wie es geschrieben
wurde, nicht so, wie es vereinbart wurde.

Der Data-Center-Connector indexiert Vorgänge (Zusammenfassung, Beschreibung, Priorität,
Status, Bearbeiter, Projekt, Zeitstempel) und Projektmetadaten. Kommentare und Anhänge
schaltet Microsoft erst auf Anfrage beim Support frei.

## Berücksichtigt der Jira-Connector die Berechtigungen aus Jira?

Ja, wenn Sie den eingeschränkten Modus wählen. Beide Connectors bieten zwei Einstellungen:

- **Everyone:** Indexierte Vorgänge sind für alle Personen im Mandanten sichtbar.
- **Only people with access to this data source:** Die Berechtigungen aus Jira werden gespiegelt. Das ist die richtige Wahl für alles Vertrauliche.

Für die Spiegelung werden Jira-Konten anhand der E-Mail-Adresse Konten in Microsoft Entra ID
zugeordnet. Weichen die Adressen ab, muss die IT-Administration eine Zuordnungsregel
anlegen; sonst sehen Personen womöglich Vorgänge nicht, die sie in Jira sehen dürfen.

Manche Berechtigungsarten lassen sich gar nicht auswerten. Der Jira-Cloud-Connector
unterstützt die Anwendungsrolle „Any user logged in“ für den Zugriff auf Vorgänge nicht. Der
Data-Center-Connector kann „Any logged-in user“, „Application access“ und manche
feldbasierte Berechtigungsarten nicht auswerten und verweigert in diesen Fällen den Zugriff.
Was der Cloud-Connector mit anderen Berechtigungsarten macht, die er nicht auflösen kann,
dokumentiert Microsoft nicht. Testen Sie deshalb ein vertrauliches Projekt, bevor Sie sich
darauf verlassen. Bei Data Center ist die Verweigerung die sichere Voreinstellung und
zugleich ein häufiger Grund, warum ein Projekt leer bleibt, während andere funktionieren.
Dann lohnt zuerst ein Blick auf das Berechtigungsschema dieses Projekts.

## Wie aktuell sind die Jira-Daten in Copilot?

Die Daten hinken Jira systembedingt hinterher. Für Jira Data Center sieht Microsoft standardmäßig
alle 15 Minuten einen inkrementellen und einmal täglich einen vollständigen Crawl vor;
beide Intervalle lassen sich ändern. Für den Jira-Cloud-Connector nennt Microsofts Übersichtsseite
(Stand 8. Oktober 2026) inkrementelle und vollständige Crawls, aber kein Standardintervall.

Berechtigungen können noch länger brauchen als Inhalte. Für den Confluence-Cloud-Connector
schreibt Microsoft, dass Berechtigungsänderungen erst beim täglichen vollständigen Crawl
übernommen werden, nicht bei den Abgleichen alle 15 Minuten. Für Jira sollten Sie dasselbe
annehmen, bis Sie es getestet haben.

In der Praxis heißt das: Fragen Sie Copilot nicht nach dem Refinement, das Sie vor zehn
Minuten beendet haben.

## Was sollte ein Produktteam zuerst prüfen?

Vier Punkte, in dieser Reihenfolge:

1. **Welches Jira Sie betreiben.** Cloud, Data Center oder Server. Für Server gibt es keinen Connector.
2. **Welche Lizenz Sie haben.** Ohne das Add-on Microsoft 365 Copilot (oder E7) antwortet Copilot nicht aus Jira, mit oder ohne Connector. Ihre Microsoft-365-Administration sieht, welche Lizenzen Ihnen zugewiesen sind.
3. **Was indexiert wird.** Fehlen die Kommentare, erhalten Sie Zusammenfassungen des Tickets, wie es geschrieben wurde, nicht wie es besprochen wurde.
4. **Ein echter Test.** Nehmen Sie ein Projekt, das Sie gut kennen, und fragen Sie etwas, das nur ein Kommentar oder eine aktuelle Änderung beantworten kann, zum Beispiel „Was haben wir in ABC-123 zum Exportformat vereinbart?“. Die Antwort zeigt die Lücken schneller als jede Dokumentation.

Bis alle vier Punkte passen, bleibt die Methode, die die meisten Teams ohnehin nutzen: den
Vorgang hineinkopieren und dem Modell den Kontext selbst mitgeben. Unser kostenloser
[Leitfaden für Product Owner](/resources/guides/ai-for-product-owners/) (auf Englisch)
enthält Prompts genau dafür.

## Wann reicht der Connector nicht aus?

Der Connector passt, wenn Sie Jira Cloud oder eine unterstützte Data-Center-Version
betreiben, Copilot-Add-on-Lizenzen haben und vor allem Vorgänge finden und zusammenfassen
wollen.

Weniger gut passt er, wenn:

- die Antwort in den Kommentaren steht,
- Sie Jira Server oder eine ältere Data-Center-Version betreiben,
- das benötigte Wissen über Jira, Confluence und weitere Systeme verteilt ist,
- der Index gar nicht in Microsoft 365 liegen soll.

Die Alternative ist ein Retrieval-System unter Ihrer Kontrolle. Es liest Jira und Confluence
über deren Schnittstellen, behält die bestehenden Berechtigungen bei, belegt jede Antwort mit
dem Vorgang oder der Seite, aus der sie stammt, und läuft auf einer Infrastruktur Ihrer Wahl.
